## 1. Problem Understanding
--------------------------------------------------

System purpose:
The system suggests available meeting time slots within a given day while respecting scheduling constraints such as working hours, busy intervals, meeting duration, buffers, and optional candidate windows.

Inputs to the system:
- day (date): The calendar day for which meeting slots are requested.
- working_hours (TimeWindow): Defines the start and end time during which meetings may be scheduled.
- busy_intervals (List[BusyInterval]): Existing commitments that prevent meetings from being scheduled during those times.
- duration (timedelta): The required meeting length.
- n (integer): Maximum number of meeting slot suggestions to return.
- buffer (timedelta, optional): Buffer time required before and after busy intervals.
- candidate_window (TimeWindow, optional): Restricts suggestions to a smaller time window.

Outputs produced by the system:
A list of Slot objects representing valid meeting start times that satisfy all scheduling constraints.

Primary goal of the system:
Generate deterministic, conflict-free meeting slot suggestions that respect all constraints and handle edge cases consistently.

--------------------------------------------------
## 2. Assumptions
--------------------------------------------------

A1: All scheduling occurs within a single calendar day.

A2: Working hours always have a valid range where start time is earlier than end time.

A3: Busy intervals represent existing commitments and must have start < end.

A4: Meeting duration is expected to be positive.

A5: Busy intervals may be unsorted or overlapping when provided as input.

A6: If no valid meeting slots exist, the system returns an empty list instead of failing.

--------------------------------------------------
## 3. Functional Requirements
--------------------------------------------------

FR1: The system shall generate meeting slot suggestions within the specified working hours.

FR2: The system shall avoid scheduling meetings that overlap with any busy interval or buffer period.

FR3: The system shall generate slot suggestions that satisfy the specified meeting duration.

FR4: The system shall return at most n valid meeting slot suggestions.

FR5: The system shall return meeting slots in deterministic chronological order.

FR6: The system shall correctly handle unsorted or overlapping busy intervals when generating slot suggestions.

--------------------------------------------------

AC1:

AC2:

AC3:
Given identical inputs to the scheduling system
When the system generates meeting slots multiple times
Then the outputs must be identical and ordered consistently.

AC4:

AC6:

## 6. Edge Cases
--------------------------------------------------

EC1:
Description: Busy intervals cover the entire working window.
Expected system behavior: The system returns an empty list of meeting slots.

EC2:
Description: Meeting duration is longer than any available gap between busy intervals.
Expected system behavior: The system returns no valid slot suggestions.

EC3:
Description: Busy intervals are provided in unsorted or overlapping order.
Expected system behavior: The system correctly processes the intervals and avoids invalid scheduling.
